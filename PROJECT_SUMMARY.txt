================================================================================
                    EVENT MANAGEMENT SYSTEM - PROJECT SUMMARY
================================================================================

📅 PROJECT OVERVIEW
================================================================================
A complete full-stack web application for managing events, registering 
attendees, and preventing duplicate registrations.

Core Features:
✅ Event Creation & Management (CRUD)
✅ User Registration & Authentication (JWT)
✅ Event Registration with Duplicate Prevention
✅ Search & Filter by Type, Date, Keywords
✅ Pagination (10 items per page)
✅ Responsive Mobile-First Design
✅ RESTful API with Proper Error Handling
✅ Docker Support (Full Stack)
✅ CI/CD Pipeline (GitHub Actions)
✅ Comprehensive Documentation

🚀 QUICK START
================================================================================

MANUAL SETUP (5 minutes):

1. Backend (Terminal 1):
   $ cd backend
   $ python -m venv venv
   $ source venv/bin/activate      # or: venv\Scripts\activate (Windows)
   $ pip install -r requirements.txt
   $ python manage.py migrate
   $ python manage.py createsuperuser
   $ python manage.py runserver

2. Frontend (Terminal 2):
   $ cd frontend
   $ npm install
   $ npm run dev

3. Open browser: http://localhost:5173

DOCKER SETUP (3 minutes):

   $ docker-compose up -d
   $ docker-compose exec backend python manage.py migrate
   $ docker-compose exec backend python manage.py createsuperuser
   
   Frontend: http://localhost:3000
   Backend: http://localhost:8000/api

🔐 AUTHENTICATION FLOW
================================================================================

1. User Registration
   POST /api/users/register/
   → Creates new user account

2. User Login
   POST /api/token/
   → Returns access_token & refresh_token

3. API Requests (Authenticated)
   Authorization: Bearer <access_token>
   → Included in all auth-required endpoints

4. Token Refresh
   POST /api/token/refresh/
   → Gets new access_token when expired

5. Protected Routes
   Frontend checks authentication state
   → Redirects to login if needed

================================================================================
💾 DATABASE SCHEMA
================================================================================

EVENT TABLE:
  id, title, description, date, type, location, capacity, image,
  created_by (FK), created_at, updated_at

REGISTRATION TABLE:
  id, event (FK), name, email, phone, created_at, updated_at
  UNIQUE: (event_id, email) - Prevents duplicate registrations

CUSTOMUSER TABLE (extends Django User):
  id, username, email, password, first_name, last_name,
  phone, profile_image, is_active, is_staff, created_at, updated_at

📡 API ENDPOINTS SUMMARY
================================================================================

AUTHENTICATION:
  POST   /api/token/                          → Get JWT token
  POST   /api/token/refresh/                  → Refresh token
  POST   /api/users/register/                 → Register user
  GET    /api/users/profile/                  → Get profile (auth)
  PUT    /api/users/profile/update/           → Update profile (auth)

EVENTS:
  GET    /api/events/                         → List all events (paginated)
  POST   /api/events/                         → Create event (auth)
  GET    /api/events/{id}/                    → Get event detail
  PUT    /api/events/{id}/                    → Update event (auth, owner)
  DELETE /api/events/{id}/                    → Delete event (auth, owner)
  GET    /api/events/upcoming/                → Get upcoming events
  GET    /api/events/my_events/               → Get user's events (auth)
  GET    /api/events/search/?q=<query>        → Search events
  GET    /api/events/{id}/registrations/      → Get event registrations

REGISTRATIONS:
  POST   /api/registrations/                  → Register for event
  GET    /api/registrations/by_email/         → Get registrations by email
  GET    /api/registrations/by_event/         → Get registrations by event
  POST   /api/registrations/check_registration/ → Check registration status
